# Recognition parity and release evidence (2026-08-13)

This document records the production contracts and regression evidence after closing the OCR
adapter audit. It covers `poe-alarm-recognition`, `poe-alarm-ocr-paddle`, and
`poe-alarm-ocr-win`. The matcher was not broadened to make the corpus pass.

## Closed production contracts

- Quick and Structured recognition are separate routes. Structured performs one target-set pass;
  it is not implemented by iterating Quick targets.
- POE2 English primary and confirmation passes use separate `OcrEngine` instances selected by
  `OcrLane`, while one process-lifetime MTA actor owns every WinRT object. Dropping and reconnecting
  clients never tears down or recreates that apartment.
- The WinRT actor queue is bounded to 16 pending commands. Submission is non-blocking and returns
  the typed public error `OcrError::WorkerQueueFull` when full.
- Every WinRT `OcrPending` owns a stale flag. Dropping it marks the request cancelled, and the actor
  skips a queued request before invoking Windows OCR. `OcrError::Cancelled` is also public and maps
  to `RecognitionError::Cancelled`.
- Paddle pending handles expose non-blocking polling. Recognition observes monitor cancellation
  while an ONNX inference is in flight and abandons the response immediately; the serial native
  actor safely finishes the already-started inference.
- Production startup is fail-closed. `ProductionRecognizer::start(profile, None)` is rejected, and
  `start_packaged` requires `onnxruntime.dll`, `PP-OCRv5_mobile_rec.onnx`, and
  `ppocrv5_dict.txt` beside the executable. Windows-only operation requires the explicitly named
  diagnostics constructor.
- Quick confirmation does not repeat a localized Paddle attempt that the primary pass already
  rejected. Switching Quick/Structured routes, changing the frame fingerprint, or changing the
  target invalidates stale progressive evidence.
- POE1 English keeps the .NET scale-2 per-band path and bounded 256-entry cache. POE2 English uses
  independent primary/confirmation caches. Structured cache keys use a sorted, deduplicated target
  signature.
- Chinese target assistance runs one shared batch inference for all unresolved targets in a crop.
  Only a normal strict match or typed `strongly_supported` result is accepted. Canonical target
  text is authoritative for lexical identity; greedy OCR text remains authoritative for displayed
  numeric values.
- The bounded segmented recovery is target-independent and cached by crop fingerprint plus width.
  Its transcript is tested against every unresolved target with the existing strict matcher. It
  never performs one inference per target.
- Assisted observations retain the source physical band identity. Weak neighboring targets and
  wrong-band substitutions are rejected.

## Regression runner semantics

- `--mode quick` and `--mode structured` are honored exactly; detailed manifests no longer mutate
  the requested mode.
- POE2 progressive output scores the primary pass and confirmation pass independently. The runner
  therefore cannot hide a primary miss behind a successful rescan.
- `assisted_sibling_collisions` is deliberately named as such; it is not presented as a corpus-wide
  false-alert rate.
- Detailed historical manifests consume `id`, `band`, `text`, and `expectedBandCount`. Their direct
  Paddle matrix asserts the declared physical row and tests all wrong physical rows as negatives.
- `total_decision_wall_ms` is the complete helper decision wall time. `primary_wall_ms` and
  `confirmation_wall_ms` split progressive work. Returned preprocessing/OCR columns describe the
  corresponding returned result and are not mislabeled as total wall time.

## Runtime ownership and cancellation boundary

- Construct one `ProductionRecognizer` per active monitor and move it to the monitor worker. The
  recognizer is `Send`, not `Sync`, and its mutable caches assume serial calls.
- Choose an immutable `RecognitionProfile` before startup. A profile or packaged-asset change
  requires a new recognizer.
- Preserve production's evaluate-before-rescan order: an accepted POE2 primary result alerts
  immediately; only a miss requests confirmation.
- Dropping a WinRT pending handle prevents queued stale work from running. An operation that has
  already entered Windows OCR cannot be interrupted safely, but the controller stops waiting at
  once and the process actor remains valid.
- Paddle has the same safe in-flight boundary: cancellation releases the controller immediately,
  while the native session finishes its current command before it can be dropped. The runtime must
  keep its retired-job/latest-intent bound; it must not create an unbounded number of replacement
  recognizers during rapid start/stop cycles.
- Treat `RecognitionError::Cancelled` after session invalidation as normal stop completion. Treat
  `OcrError::WorkerQueueFull` as transient backpressure rather than blocking the UI thread.

## Remaining non-release limitation

Native WinRT and ONNX calls are not force-cancelled after they have begun. The implemented contract
is bounded queued work plus immediate controller abandonment, not unsafe native-thread teardown.
This limitation does not weaken matching semantics or permit a late result to alert after monitor
session invalidation.
