02 · 判断 三个形态是同一个产品的三档密度，不是三个窗口
Workbench 与 Instrument 不该是两套布局。Instrument 就是 Workbench 折起「规则树 + 条件编辑器」后的运行视图；Dock 是 Instrument 再折起配置摘要后的停靠视图。同一个窗口、同一套坐标系、同一张 token 表，三档密度用 Ctrl⇧1 / 2 / 3 直达，Ctrl\ 循环。
01空间稳定：状态、目标、延迟三块在三档里坐标不变，眼睛不需要重新找。
02只有一套导航和一套快捷键，不需要记三个窗口的操作模型。
03折叠只做减法：每降一档只是隐藏一层，不重排剩下的内容 —— 这正是「不再操作界面」的前提。

现状的四个结构问题
1一次性配置（区域 / 声音 / 热键）占掉约六成面积，长期真正要盯的运行状态只有一条 34px 的横条。
2所有控件同权重、同色调、同尺寸；没有主次，眼睛没有落点。
3切换命中方式会让整块布局纵向跳动 186px，编辑态与运行态挤在同一平面。
48 套方案 × 32 条词缀的规则树被压进三个下拉框逐个点选，看不到全貌。
三个方向共用的前提
监控开始后主窗会最小化 —— 所以主窗真正的职责是「配置 + 验证」，浮窗才是长期可见面，红色告警是独占面。三个方向都按这个权重重排：目标与运行状态升到第一屏，一次性配置降为可折叠的一行摘要。
