## 本轮已接真实链路的部分(重点验收)

设置与 .NET 正式版隔离,继续使用 Rust 预览设置目录 —— 和你之前实机测过的
`rust-preview-light-cards-fix` 包**共用同一份设置**,所以旧预览版里框好的
识别区域、游戏/语言选择、目标词缀会被 GPUI 版直接读到。

### A. 设置读写

1. 启动 GPUI 版:词缀模板框应显示预览设置里已保存的目标词缀;左树显示
   当前游戏与规则(结构化规则会展开成 方案/条件 树,单条模式显示单行)。
2. 修改模板文字 → 点右栏「验证并保存」→ 状态栏右侧出现「已保存」。
3. 关闭重开程序:模板仍是修改后的内容。
4. 数值表把下限改成大于上限 → 错误行出现且「验证并保存」拒绝保存
   (状态栏提示"未通过校验");改回后可正常保存。

### B. 真实监控与命中拦截(核心)

前置:识别区域为空时启动会直接报错并回到待机,这是预期行为。
框选已接入:按 `Ctrl⇧F11` 或在「识别区域」tab 点「框选区域」,
拖拽圈出词缀区域后自动保存(Esc 取消)。

1. 打开游戏,鼠标悬停待做装备;GPUI 版点「开始监控」。
2. 状态点转墨青并呼吸,计时开始;右栏日志出现真实 OCR 行与扫描指标
   (判定/截屏耗时、扫描轮数来自 runtime 快照)。
3. 命中目标词缀 → **红色拦截窗接管输入 + 循环提示音**(runtime 内部
   已验证的 Win32 实现);UI 状态转「已命中,请确认」。
4. 点红窗上的确认按钮,或点 GPUI 窗口的「解除鼠标锁定」→ 恢复待机,
   日志记录"已确认"。
5. 全程快速点击手感:识别未决期间鼠标应完全直通(runtime 行为未动)。

### C. 三档窗口(上轮遗留修复)

1. `Ctrl⇧1/2/3` 切档(已修复:根节点现在持有初始焦点;点过输入框后
   再按也应生效)。
2. 切档后输入框内容保留;窗口尺寸 1180×620 / 720×560 / 400×620。
3. 监控中切档:状态点+文字+计时保持一致,不闪不跳。

### D. 全局热键与框选(本轮新接)

1. 程序在后台时按 `Ctrl⇧F10`:待机 → 开始监控。
2. `Ctrl⇧F11`:弹出全屏框选 overlay,拖拽后区域自动保存,
   状态栏与「识别区域」tab 显示新区域值。
3. `Ctrl⇧F12`:监控中 → 停止;命中锁定中 → 解除。
4. 命中 → 红窗确认 → 再按 `Ctrl⇧F10` 应能直接开下一轮
   (若上轮出现 BitBlt 类故障,日志会显示"运行时已重建"后即可重开)。

### E. Dock 命令行(本轮新接)

Ctrl⇧3 切到 Dock:粘贴词缀到顶部输入框 → 点「设为目标」→
目标卡与归一化预览更新、设置已保存;Ctrl⇧1 切回规则台,模板框同步。
