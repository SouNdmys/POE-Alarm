# POE Alarm 1.2.0 验证记录

日期：2026-09-23。对照版本：1.1.4（`1e161bf0c27cc19182f816ce0dd99f46bb3bc946`）。

## 发布结论

这次发布包含个人词缀库、物品导入、编辑保护、匹配边界修复，以及命中后的本地拦截加速。**没有实现网络零延迟，也不保证在 150ms 或更快连续点击时每次都能命中并拦截。**

用户要求时序重构不能牺牲命中率、命中速度或拦截速度。为此，开发中尝试过的复制调度重构没有进入本次发布：缩短初始等待、缩短被动轮询、调整迟到回复的自适应等待、重叠点击票据等，在扩大抖动测试后均存在不同场景间的得失。最终保留 1.1.4 的复制计划、重试间隔、次数预算和自适应规则。

因此，先前评审发现的「复制过程中到来的点击被结算」「迟到的第一轮回复被当作基准」等时序问题，**仍有待后续解决**，不能把本次发布描述为已修复所有快速点击漏读。

## 本次已交付

- 收藏单条词缀或完整方案，命名、分类、搜索、JSON 导入导出、删除撤销，添加时生成独立副本。收藏库和当前监控规则分开保存。
- 在「+ 词缀」中粘贴物品文本、读取并勾选完整词缀。高级描述保留复合词缀分组；普通文本提醒检查分组。导入后明确要求用户设置数值条件，默认不限制数值。
- 手动测试展开逐条解释，用于检查模板、数值条件和复合词缀占用；不加入自动监控的关键路径。
- 数值输入严格校验，防止 `7O` 等错误被降级为「不限制」；480ms 防抖保存，关闭前保存，非法输入作为草稿恢复；监控中锁定规则编辑。
- 删除撤销不会覆盖更新后的编辑。损坏配置保留 `.bad`，有效 `.bak` 可恢复；schema 升为 5，旧 schema-4 程序拒绝覆写新收藏库。
- 未勾选的词缀不占活动 32 条／8 方案上限；当前规则可保存 1024 条／128 方案。库与规则超出容量时明确拒绝，而不是静默截断。
- 跨零模板允许实际正、负值；普通正负占位仍严格区分。带客户端注解的冒号词缀不会被误当成属性段丢弃。
- 启动监控时提前准备透传鼠标钩子，确认命中才启用拦截。旧会话不能启用新会话的保护，原有超时释放和故障提示保留。
- 权限检查复用仍存活的进程句柄；剪贴板序号与所读文本在同一次锁定内采集；读取后复查前台与取消状态。持有左／右 Ctrl 时只发送 C-down/C-up，避免留下合成左 Ctrl。
- 热键替换失败保留原热键；后台初始化音频／运行时；浮窗保存显示器和相对位置，断屏后回退，重接后恢复。

## 性能证据及限制

### 本机微基准

以下是开发期间同机 Release 测试结果，单位是微秒，不是端到端游戏延迟，也不是统计上的长期保证。

| 项目 | 对照 | 优化后 |
| --- | ---: | ---: |
| 钩子准备到启用中位数 | 89.8µs | 1.1µs |
| 钩子准备到启用 P99 | 462.5µs | 13.0µs |
| 权限查询平均耗时（自身进程） | 3.508µs | 0.208µs |
| 完整规则匹配同配置交替运行均值 | 158.273µs | 156.435µs |

匹配耗时约 1% 的变化属于噪声范围，不据此宣传匹配引擎显著加速。钩子预热省去的通常不到 1ms，不能解释或消除数十毫秒的游戏／网络等待。

### 离线时序回放

直接回放 ClipboardSource 生产源码，以虚拟时钟、点击、剪贴板替代操作系统；解析器和匹配器使用实际工作区代码。每组 30 次点击，最后额外排空 1000ms，避免末尾截断。

- 点击间隔：100／120／150ms。
- 文本可用延迟：30／60／90／120／135／150／180ms。
- 复制响应时间：3／8／15ms；15ms 覆盖超过复制等待期限的迟到情况。
- 观察相位：0／5ms；各自包括无抖动及固定周期抖动。文本抖动为 0、+15、−10、+30、0、−15ms，复制抖动为 0、+7、0、−2、+12、0ms，唤醒额外 1ms。

共 252 组。分别统计「读到的轮数」和「下次点击前读到的轮数」。实验方案有低延迟收益，也有高延迟／抖动场景退化，未发布。最终发布源码与 1.1.4 在全部 252 组中的轮数、及时轮数、最大证据延迟和复制次数一致，详见 [回放结果](benchmarks/scheduler-release-1.2.0.csv)。这验证复制计划没有被此次改动改变，**不是证明旧问题已解决**。

回放假定复制发起时获取当时物品快照，不包含真实游戏内部队列、OS 抢占、渲染卡顿、物理鼠标或红窗交接时间。延迟参数也不等同于游戏显示的 ping。真实效果需要在用户的 POE1／POE2 环境复测。

真实文本回归使用仓库已有客户端语料，覆盖英文／繁中和完整复合词缀。此次未新增网页市集样本：前一轮桌面工具因无法确认浏览器网址停止；恢复后浏览器连接仍报 `nodeRepl.fetch request failed`。因此没有把市集访问、真实游戏快速点击或新界面人工交互列为已通过。

建议实际复测时先确认已有规则与勾选状态，使用可承受的测试物品；分别记录游戏、服务器、显示延迟、点击节奏，以及「没读到」「已报警但晚拦截」哪一类现象。收藏、导入和解释先用手动测试验证，确认无误后再监控。
